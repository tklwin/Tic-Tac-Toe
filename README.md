## ၁။ Minimax Depth-Adjusted Payoff (ရမှတ် တွက်ချက်မှု ဖော်မြူလာ)

Minimax သည် ရိုးရိုး Win/Loss တင်မကဘဲ **အမြန်ဆုံး နိုင်ရန်** နှင့် **ရှုံးမည့် အခြေအနေတွင် အချိန်ဆွဲ ခုခံနိုင်ရန်** Depth Penalty ကို အသုံးပြုသည်:

| ရလဒ် (Outcome) | ရမှတ် ဖော်မြူလာ | Depth 1 (၁ ကွက်တည်းဖြင့်) | Depth 3 (၃ ကွက်ကြာမှ) | အဓိပ္ပာယ် နှင့် ဆုံးဖြတ်ချက် |
| :--- | :---: | :---: | :---: | :--- |
| **AI နိုင်လျှင် (Win)** | `+10 - depth` | $+10 - 1 = \mathbf{+9}$ | $+10 - 3 = \mathbf{+7}$ | $\mathbf{+9 > +7}$ ဖြစ်၍ AI သည် အမြန်ဆုံး နိုင်မည့်လမ်းကို ရွေးချယ်သည်။ |
| **AI ရှုံးလျှင် (Loss)** | `depth - 10` | $1 - 10 = \mathbf{-9}$ | $3 - 10 = \mathbf{-7}$ | $\mathbf{-7 > -9}$ ဖြစ်၍ AI သည် ရှုံးမည့်အဖြစ်ကို အတတ်နိုင်ဆုံး အချိန်ဆွဲပြီး ရုန်းကန်ခုခံသည်။ |
| **သရေ (Draw)** | `0` | $\mathbf{0}$ | $\mathbf{0}$ | Perfect Play တွင် သရေရလဒ်သည် သီအိုရီအရ အာမခံချက်ရှိသော Equilibrium ဖြစ်သည်။ |

> **💡 ဥပမာ (-6 vs -8):**  
> Leaderboard တွင် `-8` (နောက်တစ်လှည့်တွင် ချက်ချင်းရှုံးမည့်အကွက်) ထက် **`-6` (နောက် ၂ လှည့်ကြာမှ ရှုံးမည့်အကွက်)** သည် ရမှတ်ပိုများသဖြင့် AI က အကောင်းဆုံး ခုခံမှု (`Best Defense`) အဖြစ် ရွေးချယ်ပါသည်။

## ၂။ Alpha-Beta Cutoffs & Pruning သဘောတရား

Alpha-Beta Pruning သည် Minimax ၏ အဆုံးအဖြတ် (Decision) ကို မပြောင်းလဲစေဘဲ မလိုအပ်သော အကိုင်းအခက် ၉၃% ကျော်ကို ဖြတ်တောက် (Cutoff) ပေးပါသည်:

### Alpha (α) နှင့် Beta (β) ဆိုသည်မှာ:
* **Alpha ($\alpha$):** Maximize ကစားသူ (မိမိ) အတွက် လက်ရှိ အာမခံချက်ရှိနေသော **အမြင့်ဆုံးရမှတ် (Best Score Guaranteed)**။
* **Beta ($\beta$):** Minimize ကစားသူ (ပြိုင်ဘက်) က မိမိအား ပေးမည့် **အနိမ့်ဆုံးရမှတ် (Lowest Score Forced)**။

### Cutoff ဖြစ်ပေါ်ပုံ လက်တွေ့ ဥပမာ:
1. မိမိလက်ထဲတွင် **သရေရလဒ် ($\alpha = 0$)** သေချာပေါက် ရထားပြီးသော အကွက်တစ်ခု ရှိနေပြီ ဆိုပါစို့။
2. အခြား အကွက်အသစ်တစ်ခုကို စမ်းစစ်သည့်အခါ ပြိုင်ဘက်က မိမိအား ရှုံးစေမည့် **Score -6 ($\beta = -6$)** အထိ ချိုးနှိမ်နိုင်သည်ကို တွေ့ရှိရသည်။
3. ဤတွင် **$\beta \le \alpha$ ($-6 \le 0$)** ဖြစ်သွားသဖြင့်:
   * မိမိလက်ထဲတွင် $0$ ရှိနေပြီးဖြစ်၍ $-6$ ရမည့် ဤလမ်းကြောင်းကို မိမိ ဘယ်သောအခါမျှ မရွေးချယ်ပါ။
   * ပြိုင်ဘက်ကလည်း $0$ ထက် ပိုသာသော အမှတ်ကို ဤလမ်းကြောင်းတွင် ပေးမည် မဟုတ်ပါ။
4. ထို့ကြောင့် ဤအကိုင်းအခက်၏ ကျန်ရှိသော အကွက်များကို ဆက်လက် မတွက်ချက်တော့ဘဲ **ချက်ချင်း ဖြတ်ချ (Cutoff)** ပစ်လိုက်ပါသည်။

## ၃။ Heuristic Agent Decision Hierarchy (စည်းမျဉ်း ဦးစားပေး စနစ်)

`HeuristicAgent` သည် ရှုပ်ထွေးသော Tree Search မသုံးဘဲ အောက်ပါ အဆင့် ၅ ဆင့်အတိုင်း ဦးစားပေး ဆုံးဖြတ်ပါသည်:

$$\text{Immediate Win} \;\longrightarrow\; \text{Immediate Block} \;\longrightarrow\; \text{Center (Cell 4)} \;\longrightarrow\; \text{Corners (0, 2, 6, 8)} \;\longrightarrow\; \text{Edges (1, 3, 5, 7)}$$

1. **Immediate Win:** ကိုယ်တိုင် ၁ ကွက်တည်းဖြင့် နိုင်မည့် အကွက်ရှိပါက ချက်ချင်း ယူသည်။
2. **Immediate Block:** ပြိုင်ဘက် နောက်တစ်ကွက်တွင် နိုင်တော့မည်ဆိုပါက ချက်ချင်း ပိတ်သည်။
3. **Center (Position 4):** အနိုင်လိုင်း ၄ လိုင်း ပါဝင်သော အလယ်ကွက်ကို ဦးစားပေး ယူသည်။
4. **Corners (0, 2, 6, 8):** အနိုင်လိုင်း ၃ လိုင်းစီ ပါဝင်သော ထောင့်ကွက်များကို ယူသည်။
5. **Edges (1, 3, 5, 7):** အနိုင်လိုင်း ၂ လိုင်းသာ ပါဝင်သော ဘေးစွန်းကွက်များကို နောက်ဆုံးမှ ယူသည်။

## ၄။ Generative AI Connections (LLM များနှင့် ဆက်စပ်မှု)

Classical Adversarial Search (Closed/Deterministic) ၏ Tree Search သဘောတရားများကို Modern Generative AI တွင် အောက်ပါအတိုင်း အသုံးချပါသည်:

1. **Monte Carlo Tree Search (MCTS):**  
   * နေရာအားလုံး မရှာဘဲ Simulation Rollouts များဖြင့် အလားအလာအကောင်းဆုံး လမ်းကြောင်းကို ရွေးချယ်ခြင်း *(AlphaGo နှင့် Test-time Reasoning Compute)*။
2. **Tree of Thoughts (ToT):**  
   * LLM ၏ တွေးခေါ်မှု အဆင့် (Reasoning Steps) များကို Tree Nodes အဖြစ် ခွဲထုတ်စဉ်းစားစေပြီး မှားယွင်းပါက နောက်ပြန်ဆုတ် (Backtrack) ခြင်း။
3. **Process Reward Models (PRMs):**  
   * အဖြေနောက်ဆုံးမှ အမှတ်မပေးဘဲ၊ သင်္ချာတွက်သလို အဆင့်တစ်ဆင့်ချင်းစီ၏ အရည်အသွေးကို Step-by-step အမှတ်ပေးသော Heuristic Evaluation စနစ်။
